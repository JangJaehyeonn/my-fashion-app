# 0012. 살까 말까 속성 수정 후 재판정

- 상태: 채택
- 날짜: 2026-11-22
- 관련: FR-13, #29

## 배경
AI 분류가 틀리면(예: 하의를 상의로) 다른 카테고리와 비교한 판정이 나온다. 사용자가 속성을 고치면 사진을 다시 분류하지 않고
고친 속성으로 다시 판정해야 한다. 판정 기록(FR-12, ADR 0011)과 BUY 때 쓰는 초안(Redis)이 이미 있고,
재판정 중에 다른 요청으로 BUY·SKIP이 끝날 수도 있다.

## 결정
`PATCH /api/purchase-checks/{id}/attributes`는 같은 기록을 갱신한다. 기록·초안의 분석값에 고친 값(생략은 그대로)을 덮어쓰고
임베딩부터 FR-11과 같은 경로(유사도 → +N → 규칙 판정 → 문장)로 다시 계산한다. 기록 갱신은
`decision = 'UNDECIDED'`일 때만 바뀌는 조건부 UPDATE로 해서 그사이 결정이 끝났으면 409를 돌려준다.
결정이 끝난 건은 409, 30분이 지나 사진이 지워진 건은 결정 API와 같이 410이다. 재판정은 정정이므로 하루 30회 한도를 쓰지 않는다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 새 판정 기록을 만든다 | 기록이 불변 | 같은 사진에 기록이 둘, 임시 사진 복사 필요 | 기록 목록이 중복되고 ADR 0011이 같은 기록 갱신을 전제 |
| 엔티티를 읽어 save로 덮어쓴다 | 코드가 단순 | 재판정 중 끝난 BUY 결정을 UNDECIDED로 되돌릴 수 있다 | 동시성 문제 |
| 재판정도 하루 한도에 센다 | AI 비용 상한이 단순 | 분류 오류를 고치는 사용자가 손해 | 분류 호출이 없어 비용이 작고, 열린 건만 고칠 수 있어 30분 안으로 제한된다 |

## 결과
분류 오류를 고친 판정이 같은 기록에 남고 BUY는 고친 속성·임베딩으로 옷을 만든다. 초안이 없으면(Redis 장애)
핏·소재·패턴·계절은 비어 있는 채로 재판정한다. 재판정 남용이 보이면 기록별 횟수 제한을 검토한다.
