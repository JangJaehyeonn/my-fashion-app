# 0021. 첫 실행 온보딩: 옷장 5벌 미만이면 메인 진입 때 한 번, '나중에 하기'는 기기에 날짜로 저장

- 상태: 채택
- 날짜: 2026-11-23
- 관련: FR-22, #59

## 배경
FR-22는 가입 직후 옷장이 5벌 미만이면 온보딩('5벌만 등록하면 살까 말까를 쓸 수 있어요', 갤러리 다중 등록, 진행 표시 3/5, 나중에 하기)을 보여 주고,
5벌이 되면 '이제 살까 말까를 써볼 수 있어요'와 쇼핑 탭으로 가기를 보여 주라고 한다.
인수 기준은 "0벌 신규 계정은 로그인 후 보이고 5벌 이상은 안 보인다", "나중에 하기를 누르면 같은 날 다시 뜨지 않는다"이다.
서버에는 '가입 직후인지'나 온보딩 표시 여부를 알려 주는 필드가 없다.

## 결정
- 표시 조건은 앱의 `OnboardingGate`가 정한다: 오늘 '나중에 하기'를 누르지 않았고, `GET /api/clothes` 개수가 5 미만이면 보인다.
  기준 5는 살까 말까의 최소 옷장 수(백엔드 `PurchaseCheckService`, 앱 `ShoppingHomeState.MIN_CLOSET_SIZE`)와 같다.
- 판단 시점: 메인 탭이 보일 때 `MainViewModel`이 만 14세 확인이 끝난 뒤에 한 번 판단한다(로그인 세션마다 한 번, 로그아웃하면 초기화).
  옷장을 못 불러오면 보이지 않고 다음 메인 진입 때 다시 판단한다.
- '나중에 하기'는 그날 날짜(주입한 `Clock` 기준 "YYYY-MM-DD")를 SharedPreferences(`onboarding`)에 저장한다. 서버 API는 추가하지 않는다.
- 온보딩 등록은 옷장 탭과 같은 방식(사진 압축·FR-21 배경 제거 → `POST /api/clothes`, 한 장씩 차례로)이며, 성공할 때마다 진행 수가 1 늘고
  끝나면 `ClosetChanges`로 옷장 탭을 다시 불러오게 한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 서버에 온보딩 완료·미루기 상태 저장 | 기기를 바꿔도 같음 | DB 컬럼·API 추가, 백엔드 작업 | 요구사항은 앱 화면 하나이고 '같은 날'만 막으면 된다 |
| 회원가입 직후에만 한 번 보여 줌 | 단순 | 소셜 첫 로그인·재설치 구분이 어렵고, 한 번 놓치면 다시 볼 수 없음 | 옷장 수 기준이 인수 기준과 바로 맞는다 |
| 옷장 탭 ViewModel을 온보딩에서 재사용 | 업로드 코드 중복 없음 | 옷장 탭 상태(정렬·요약·URL 등록)까지 따라오고 진행 수 테스트가 어려움 | 온보딩 전용 ViewModel로 진행 상태만 검증 |

## 결과
옷이 5벌 미만인 기존 계정도 날마다 한 번 온보딩을 볼 수 있다(나중에 하기로 그날은 닫힌다). 5벌이 되면 다시 보이지 않는다.
미루기 날짜는 계정 구분 없이 기기에 저장되므로, 같은 날 같은 기기에서 다른 계정으로 바꾸면 그 계정도 그날은 보이지 않는다.
옷 삭제로 5벌 미만이 되면 다시 보일 수 있다. 문제가 되면 서버에 표시 상태를 두는 방안을 다시 본다.
