# 0009. 착용 기록 저장 형식과 날짜 규칙 (wear_records)

- 상태: 채택
- 날짜: 2026-11-22
- 관련: FR-10, #26

## 배경
FR-10은 `POST /api/wears {clothesIds[], date}`로 착용을 기록하고(같은 날 같은 옷은 한 번만), 옷 목록에 옷별 `wearCount`·`lastWornAt`을,
`GET /api/wears/summary`로 이번 주·이번 달 착용 횟수와 가장 많이 입은 옷을 주라고 한다. 탈퇴 시 기록을 지우고, 남의 옷 ID가 섞이면 400이다.
요구사항에는 '오늘'의 시간대, 주의 시작 요일, '횟수'의 단위, '가장 많이 입은 옷'의 기간이 없다. 이 값들은 이후 FR-11(예상 착용 횟수)·
FR-29(오래 안 입은 옷)의 규칙 계산 입력이 되므로 결정적으로 정해 둬야 한다. DB 변경은 nullable 추가와 멱등 SQL만 허용된다.

## 결정
- 새 테이블 `wear_records(id, user_id, clothes_id, worn_on DATE, created_at)`에 **옷 한 벌 × 하루 = 한 행**으로 저장한다.
  `(clothes_id, worn_on)` 유일 제약을 두고 `INSERT … ON CONFLICT DO NOTHING`으로 넣어, 같은 날 중복 기록은 동시 요청이어도 한 행이 된다.
- 요청의 옷 ID는 모두 그 사용자의 옷이어야 한다. 하나라도 아니면 400(`INVALID_WEAR_CLOTHES`)이고 한 트랜잭션이라 아무것도 남지 않는다.
  ID·날짜 형식 오류, 빈 목록, 미래 날짜는 400(`INVALID_WEAR_REQUEST`).
- '오늘'은 주입한 `Clock`의 시각을 **Asia/Seoul** 달력 날짜로 바꾼 값이다 (`WearCalendar`). 서버 시간대(컨테이너는 보통 UTC)와 무관하다.
- 주는 **월요일 시작**, 이번 주 = 이번 주 월요일 ~ 오늘, 이번 달 = 1일 ~ 오늘.
- 요약의 횟수는 **기록 행 수**(옷 단위)다. 코디 3벌을 하루 입으면 3이다. 옷 목록의 `wearCount`도 같은 단위(그 옷을 입은 날 수)라 서로 맞는다.
- 가장 많이 입은 옷은 **전체 기간** 착용 일수가 가장 많은 옷이고, 같으면 마지막 착용일이 최근인 옷, 그다음 id가 작은 옷이다. 기록이 없으면 null.
- `user_id`·`clothes_id`에 FK를 걸지 않는다. 옷 삭제(`ClothesService.delete`)와 탈퇴(`AccountDeletionService`)가 같은 트랜잭션에서 먼저 지운다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 코디(날짜) 단위 한 행 + 옷 ID 배열 | 코디 단위 통계가 쉬움 | 옷별 횟수·중복 판정에 배열 연산, 같은 날 두 번 기록 시 병합 규칙 필요 | 요구사항의 기준이 옷별(wearCount·같은 날 같은 옷) |
| `clothes`에 wear_count·last_worn_at 컬럼 | 목록 조회가 단순 | 날짜별 기록이 없어 주·월 요약·90일 창(FR-11) 계산 불가, 날짜 지정 기록과 중복 판정 불가 | 요약 요구 |
| 서버 기본 시간대로 '오늘' | 코드 변경 없음 | UTC 서버에서 한국 0~9시 기록이 전날로 저장 | 사용자는 한국 날짜로 생각함 |
| 일요일 시작 주 | 미국식 달력과 같음 | 국내 달력·ISO와 다름 | ISO 8601·국내 관례 |
| 이미 있으면 조회 후 저장 | 네이티브 SQL 없음 | 동시 요청 시 유일 제약 위반 500 | 동시성 안전 |
| FK(ON DELETE CASCADE) | DB가 삭제 보장 | 기존 운영 DB에 제약 추가, 다른 테이블(consent_records)과 방식이 달라짐 | ADR 0005와 같은 방식 유지 |

## 결과
- 같은 입력·같은 시계면 같은 결과가 나온다. 이후 규칙(FR-11·FR-29)은 `wear_records`의 날짜 행을 그대로 쓴다.
- 기록 수는 옷 수 × 날짜 수만큼 늘어난다. 사용자·날짜 인덱스(`idx_wear_records_user_day`)로 요약을 계산한다. 목록 조회 때 사용자별 집계 쿼리가 하나 더 돈다.
- 착용 기록 삭제(취소) API는 요구사항에 없어 만들지 않았다. 필요해지면 같은 유일 키로 지운다.
- 해외 사용자가 생기면 '오늘'을 사용자 시간대로 바꾸는 것을 다시 검토한다.
