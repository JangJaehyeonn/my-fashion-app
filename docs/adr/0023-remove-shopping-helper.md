# 0023. 쇼핑 도우미 제거와 쇼핑몰 검색어 프롬프트 모듈

- 상태: 채택
- 날짜: 2026-11-24
- 관련: FR-23, #70

## 배경
예산·상황을 받아 LLM이 아이템과 가격을 지어내던 쇼핑 도우미(`POST /api/shopping/recommend`)는 탭에서 빠진 뒤에도
백엔드 `domain/shopping`, AI 서버 라우터, 앱 Retrofit 인터페이스, 홈 요약 API, k6 스크립트에 남아 있었다.
"판정과 숫자는 규칙으로 정한다"는 원칙과도 맞지 않는다 (예상 가격·코디 개수를 LLM이 정함).
다만 쇼핑몰·검색어를 제안하는 프롬프트는 FR-25(다음에 살 옷 추천)에서 다시 쓴다.

## 결정
쇼핑 도우미의 API·서비스·요청/응답 클래스·앱 데이터 계층을 지우고, 홈 요약(`/api/home/summary`)은 상황 코디 추천만 담는다
(`budget` 입력과 `shoppingRecommendation` 필드 제거). 쇼핑몰 검색어 프롬프트는 라우터·OpenAI 호출 없이
`ai-server/app/services/shopping_keywords.py`에 프롬프트 생성·응답 파싱 함수로만 남긴다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 엔드포인트를 남기고 숨김 유지 | 변경 없음 | 죽은 코드·OpenAI 비용 경로가 남음 | 요구사항이 제거를 요구 |
| 프롬프트까지 모두 삭제 | 가장 단순 | FR-25에서 다시 작성해야 함 | 요구사항이 재사용 모듈을 요구 |
| 기존 `shopping_service.py`를 이름만 남김 | 수정 적음 | 예산·가격 생성 등 도우미 전용 로직이 섞여 있음 | 검색어 부분만 분리하는 편이 명확 |

## 결과
- 앱 하단 '쇼핑' 탭(쇼핑 홈, `ui/shopping`)은 살까 말까 화면이라 그대로 둔다.
- 홈 요약 응답에서 `shoppingRecommendation`이 빠진다. 앱은 이 API를 부르지 않아 영향이 없다.
- FR-25가 `build_search_keyword_prompt`·`parse_search_keywords`를 쓰는 라우터를 붙일 때 이 모듈의 형식을 다시 본다.
