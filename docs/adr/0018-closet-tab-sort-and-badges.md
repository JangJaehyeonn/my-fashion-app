# 0018. 옷장 탭: 서버 값으로 앱에서 정렬하고, NEW 배지는 이번 세션에 산 옷으로 정한다

- 상태: 채택
- 날짜: 2026-11-23
- 관련: FR-19, #56

## 배경
옷장 탭은 카드마다 코디 수와 착용 횟수를 보여주고, 코디 많은 순 / 적게 입은 순 / 최근 등록으로 정렬해야 한다.
코디 수(FR-09)와 착용 횟수·마지막 착용일(FR-10)은 이미 `GET /api/clothes` 응답의 옷마다 들어 있다.
"방금 산 옷" NEW 배지는 서버에 따로 표시가 없고, 살까 말까 "살래요"(FR-18)로 옷장에 들어간 옷을 가리킨다.

## 결정
- 정렬·필터·배지·요약 계산은 앱의 순수 함수(`ui/closet/ClosetList.kt`)가 서버 값만으로 한다. 동률은 최근 등록 순, 그다음 id로 깨서 항상 같은 순서가 된다.
  적게 입은 순은 착용 횟수가 같으면 마지막 착용일이 오래된(안 입은 옷 먼저) 순이다.
- 요약 줄의 "만들 수 있는 코디"는 `GET /api/clothes/summary`, "이번 달 착용"은 `GET /api/wears/summary`의 `monthCount`를 그대로 쓰고,
  "잘 안 입는 옷"은 분류된 옷 중 착용 0회인 옷의 수다.
- NEW 배지는 `ClosetChanges.notifyBought`로 이번 앱 세션에 "살래요"한 옷 id를 메모리에 기억해 붙인다. 백엔드·DB는 바꾸지 않는다.
- 옷을 등록·삭제하면 다른 옷의 코디 수도 바뀌므로 목록을 다시 불러 서버 값으로 맞춘다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 서버 정렬 파라미터(`?sort=`) | 정렬 규칙이 서버 한 곳 | 백엔드 API 변경, 탭마다 재요청 | 목록이 작고 필요한 값이 이미 응답에 있다 |
| 서버에 "산 옷" 표시 컬럼·응답 필드 추가 | 앱을 껐다 켜도 NEW 유지 | 스키마·API 변경, 요구사항 범위 밖 | 이 이슈는 앱 화면 요구사항이다 |
| 등록 후 N일 이내를 NEW로 | 서버 변경 없음 | 사진으로 등록한 옷과 산 옷을 구분하지 못함 | ui-spec은 "방금 산 옷"을 가리킨다 |

## 결과
서버를 바꾸지 않고 카드 값이 서버 값과 정확히 같다. 정렬·배지 조건은 JVM 단위 테스트로 검증한다.
NEW 배지는 앱을 다시 시작하면 사라진다. 사용자가 NEW를 오래 보고 싶어 한다는 신고가 있으면 서버 표시 대안을 다시 본다.
