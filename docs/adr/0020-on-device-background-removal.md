# 0020. 옷 사진 배경 제거: ML Kit 피사체 분리를 기기 안에서 쓰고, 실패하면 원본을 올린다

- 상태: 채택
- 날짜: 2026-11-23
- 관련: FR-21, #58

## 배경
FR-21은 옷 등록과 살까 말까 업로드 전에 사진 배경을 지우고 연한 단색 배경에 합성한 뒤 기존 압축(긴 변 1024px JPEG)을 적용하도록 요구한다.
서버 비용 없이 기기 안에서 처리해야 하고, 분리에 실패하거나 피사체가 너무 작으면 원본을 쓰며, 설정에서 끌 수 있어야 한다.
앱에는 이미지 분할 라이브러리가 없어 새 의존성이 필요하다.

## 결정
- 의존성: `com.google.android.gms:play-services-mlkit-subject-segmentation:16.0.0-beta1` (ML Kit 피사체 분리).
  모델은 Google Play 서비스가 내려받고 추론은 기기 안에서 한다. 매니페스트 `com.google.mlkit.vision.DEPENDENCIES = subject_segment`로 설치 때 미리 받는다.
- 처리 순서: 디코딩·EXIF 회전·긴 변 1024px 축소(`ImageCompressor.decode`) → 배경 제거(`BackgroundRemover`) → JPEG 품질 80 인코딩(`ImageCompressor.encode`).
  큰 원본 그대로 분리하면 메모리와 시간이 커서, 업로드 크기로 줄인 뒤 분리한다. 결과는 "배경 제거 후 기존 압축"과 같다.
- 합성: 픽셀별 전경 신뢰도(0~1)로 원본과 배경색 `#F2F2F0`(연한 무채색 회색)을 섞는다. 색이 있는 배경은 AI 색상 분류를 흔들 수 있어 무채색으로 정했다.
- 원본을 쓰는 경우(모두 예외 없이 원본 반환, 등록은 그대로 진행):
  설정 꺼짐 / 이미지가 1024×1024 픽셀 초과 / 분리 오류(모델 미설치 포함) / 8초 초과 / 마스크 크기 불일치 / 신뢰도 0.5 이상 픽셀이 전체의 5% 미만(피사체가 너무 작음).
- 판단 로직(`BackgroundRemover`)은 `IntArray`·`FloatArray`만 다루고 분리기는 `SubjectSegmenter` 인터페이스로 주입해 JVM 단위 테스트로 검증한다.
  ML Kit 호출은 `MlKitSubjectSegmenter` 한 곳에만 둔다.
- 옷장 등록(`ClosetViewModel`)도 살까 말까와 같은 `UploadImageCompressor`를 주입받아 같은 경로를 쓴다.
- 설정: 마이 > 설정의 "옷 사진 배경 지우기" 스위치. 기본값 켬, SharedPreferences(`image_settings`)에 저장한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| ML Kit 셀피 분할(selfie segmentation) | 모델이 앱에 포함 | 사람 전용이라 옷만 찍은 사진을 못 나눈다 | 옷 사진에 맞지 않음 |
| 서버(AI 서버)에서 배경 제거 | 기기 성능과 무관 | 서버 비용·전송 증가, 요구사항이 기기 안 처리 | 요구사항 위반 |
| 자체 TFLite 모델 번들 | 오프라인에서 바로 동작 | APK가 커지고 모델 관리 부담 | 유지 비용 |
| 원본 해상도에서 분리 후 압축 | 경계가 조금 더 정밀 | 수천만 픽셀 처리로 느리고 메모리 부족 위험 | 업로드 해상도로 충분 |

## 결과
배경 제거가 켜져 있으면 업로드 사진의 배경이 단색이 되어 분류·유사도 계산에 배경 잡음이 줄어든다.
Google Play 서비스가 없거나 모델을 아직 받지 못한 기기에서는 원본 사진이 올라가므로 기존 동작과 같다.
ML Kit 피사체 분리는 beta 버전이라 API가 바뀌면 `MlKitSubjectSegmenter`만 고친다. 사진은 1장당 수백 ms가 더 걸릴 수 있다.
