# 0002. 미분류 옷의 저장 형식과 분류 실패 표시

- 상태: 채택
- 날짜: 2026-11-21
- 관련: FR-01, #4

## 배경
옷 등록 중 AI 분류가 실패(연결 실패·타임아웃·5xx·잘못된 응답)하면 지금까지는 등록 자체가 실패했다.
FR-01은 사진은 저장하고 카테고리·색상을 미분류로 둔 채 등록하고, 응답에 분류 실패 여부를 넣으라고 한다.
미분류 옷은 코디 추천·코디 수 계산·유사 검색에서 빠져야 하고, 사용자가 직접 고치거나 다시 분류할 수 있어야 한다.
DB 변경은 nullable 추가만 허용되고 기존 데이터를 바꾸면 안 된다.

## 결정
`clothes.category` 문자열 컬럼에 새 값 `UNCLASSIFIED`를 저장하고(색상·이름은 null), 응답의 `classificationFailed`는
카테고리가 `UNCLASSIFIED`인지로 계산한다. 새 컬럼은 만들지 않는다.
재분류는 저장소에서 원본 바이트를 다시 읽어(`ImageStorage.readBytes`) AI 서버에 보낸다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| `classification_failed` boolean 컬럼 추가 | 실패 이력이 카테고리와 따로 남음 | 컬럼·멱등 SQL 필요, 사용자가 카테고리를 고친 뒤 두 값을 맞추는 규칙이 따로 필요 | 두 값이 어긋날 수 있고, 요구사항은 "지금 미분류인가"만 필요 |
| 카테고리를 null로 저장 | 새 enum 값 불필요 | 기존 `ClothesCategory.from(null)`이 ETC로 바꿔 옛 데이터와 구분 불가 | 옛 행과 섞임 |
| 실패 시 ETC로 저장 | 앱 변경 없음 | 진짜 '기타'와 구분 불가, 추천에서 뺄 수 없음 | 요구사항 위반 |

## 결과
- 스키마 변경·백필이 없다 (category는 이미 자유 문자열 컬럼). 사용자가 카테고리를 고치거나 재분류에 성공하면 자동으로 실패 표시가 풀린다.
- 사용자가 PATCH로 `UNCLASSIFIED`를 지정할 수는 없다 (400). AI가 `UNCLASSIFIED`를 돌려주면 잘못된 응답으로 본다.
- 옛 앱 빌드는 모르는 enum 값을 null로 읽으므로, 앱 모델에 `UNCLASSIFIED`를 추가했다 (화면 처리는 FR-02).
- 실패 이력(언제, 왜 실패했는지)이 필요해지면 별도 컬럼이나 이벤트로 다시 검토한다.
