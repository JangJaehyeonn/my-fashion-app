# 0022. 홈 동선 날씨·세탁 바구니 화면: 문구는 서버 규칙 결과로만, 출퇴근 설정은 별도 화면

- 상태: 채택
- 날짜: 2026-11-23
- 관련: FR-30, #60 (FR-27 / ADR 0014, FR-28 / ADR 0016, FR-29 / ADR 0015)

## 배경
FR-30은 홈 날씨 카드를 동선 타임라인('8시 3° → 13시 12° → 19시 7° · 일교차 9°')으로 바꾸고, 일교차·비 규칙이 적용되면 안내 문구를,
코디 카드 위에 '입을 수 있는 옷 N벌 중에서 · 세탁 중 N벌 제외'를, 입었어요 뒤에 '세탁에 넣기'를, 되살린 조합에 '오랜만이에요'를 보이라고 한다.
옷장 탭에는 세탁 바구니 칩과 '세탁 끝' 일괄 버튼, 마이 탭에는 출퇴근 시각·이동 방식 설정이 필요하다.
요구사항에는 안내 문구를 언제(추천 전·후) 무엇으로 판단하는지, 마이에서 저장한 값이 홈에 언제 반영되는지, 기존 홈 ViewModel을 어떻게 테스트할지가 없다.

## 결정
- **안내 문구**: 앱이 일교차·강수 확률로 직접 판단하지 않는다. 추천 응답 `appliedRules`(FR-28, 서버 규칙 결과)에 `TEMP_RANGE`·`RAIN`이 있을 때만
  '외투를 벗어도 괜찮은 코디로 골랐어요'·'비 소식이 있어 스웨이드·흰 신발은 뺐어요'를 날씨 카드에 보인다. 그래서 문구는 추천을 받은 뒤 나타난다.
  '일교차' 굵게(8° 이상)는 ui-spec의 표시 규칙이라 앱 상수(`HomeTexts.RANGE_EMPHASIS_DEGREES`)로 둔다 — 후보 판정에는 쓰지 않는다.
- **타임라인**: `GET /api/weather/day`를 현재 날씨와 같은 좌표로 부른다. 실패하면 타임라인만 숨기고 현재 날씨 카드는 그대로 둔다.
  추천 요청에도 같은 `lat`·`lon`을 보내 서버가 동선 규칙을 적용하게 한다.
- **출퇴근 반영**: 마이 > '출퇴근 시각·이동 방식' 화면(`CommuteSettingsScreen`)에서 `PUT /api/users/me`로 저장한다.
  서버가 체형 필드를 받은 값으로 덮어쓰므로 현재 체형·취향 값을 그대로 함께 보내고, 출퇴근 값은 비우면 `""`(서버에서 지움)로 보낸다.
  홈 탭은 보일 때마다 `refreshTimeline()`으로 타임라인을 다시 불러온다(서버 캐시가 있어 예보 API를 다시 부르지 않는다). 공유 이벤트 객체는 두지 않는다.
- **세탁**: 홈의 '입은 옷 세탁에 넣기'와 옷장의 '세탁 끝'은 `PATCH /api/clothes/status`(FR-27) 한 번으로 여러 벌을 바꾸고 `ClosetChanges`로 옷장을 다시 불러온다.
  '입을 수 있는 옷' 수는 서버 `available`을 센다(옛 서버라 없으면 분류됨 ∧ 세탁 중 아님).
- **테스트**: `HomeViewModel`이 Android `Context`가 필요한 `LocationProvider` 대신 `DeviceLocation` 인터페이스를 받게 하고 Hilt `LocationModule`로 묶었다.
  그래서 JVM 단위 테스트로 타임라인·문구·revived 표시를 검증한다(ADR 0003).

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 앱이 `tempRange ≥ 8`, 강수 확률 ≥ 60으로 문구 표시 | 추천 전에도 문구가 보인다 | 기준값이 서버 규칙 파일과 따로 놀고, 남는 조합이 없어 규칙을 안 쓴 날에도 '골랐어요'라고 말함 | 판정은 서버 규칙, 앱은 결과 표시만 |
| 홈 진입 때 자동 추천 | 문구가 바로 보인다 | 탭을 열 때마다 AI 호출 비용, 요구사항에 없음 | 기존 '오늘의 코디 추천' 버튼 흐름 유지 |
| 출퇴근 저장 후 공유 이벤트(`ClosetChanges` 같은 싱글톤)로 홈에 알림 | 저장했을 때만 다시 부른다 | 객체가 하나 늘고, 다른 기기·웹에서 바꾼 값은 반영 못 함 | 탭이 보일 때 다시 부르는 기존 패턴(FR-20 주간 카드)과 맞춤 |
| 출퇴근 설정을 체형·취향 화면에 합침 | 화면 수가 줄어든다 | ui-spec 설정 목록에 별도 행으로 있음 | 명세대로 별도 행·화면 |

## 결과
- 안내 문구는 늘 서버가 실제로 적용한 규칙과 일치한다. 대신 추천 버튼을 누르기 전에는 타임라인만 보인다.
- 이동 방식은 저장만 하고 규칙에는 아직 쓰지 않는다(ADR 0016). 규칙에 쓰게 되면 앱 변경 없이 `appliedRules`에 새 값과 문구를 더한다.
- 다른 화면 ViewModel도 위치가 필요하면 `DeviceLocation`을 주입받는다.
